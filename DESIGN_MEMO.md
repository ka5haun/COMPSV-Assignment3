For this project, I implemented a custom stack and queue using a linked structure made from a Node class. Each Node stores a value and a reference to the next Node. I used this approach instead of Python's built-in list or queue structures so that I could better understand how these data structures work internally.(still learning) The stack is used in the Undo/Redo Manager. A stack follows the Last In, First Out (LIFO) principle. When a user performs an action, the action is pushed onto the undo stack. When the user selects undo, the most recent action is popped from the undo stack and pushed onto the redo stack. Selecting redo moves the action back to the undo stack. I also implemented push, pop, peek, and print operations for the stack. The queue is used in the Help Desk Ticketing System. A queue follows the First In, First Out (FIFO) principle. Customers are added at the rear of the queue using enqueue. When a customer is helped, dequeue removes the customer at the front. The peek operation allows the program to view the next customer without removing them. I tested both programs with multiple interactions and edge cases. For the Stack, I tested performing, undoing, and redoing actions, including attempting to undo an empty stack. For the Queue, I added multiple customers and confirmed they were helped in the same order they entered. I also tested peek and attempted to help a customer when the queue was empty.
